**What the code does**
- `register(user, char[])` / `authenticate(user, char[], [remoteAddr])` → `Result` with a user-safe `userMessage()` and an audit-only `auditReason()`.
- Passwords stored only as PBKDF2-HMAC-SHA256 (120k rounds, per-account random salt) in a self-describing `pbkdf2-sha256$rounds$salt$key` record; plaintext never stored, logged or stringified.
- Five outcomes cover both success and failure plus the surrounding real cases: `SUCCESS`, `INVALID_CREDENTIALS`, `ACCOUNT_LOCKED`, `ACCOUNT_DISABLED`, `INVALID_INPUT`.
- **Every attempt writes exactly one audit record** (plus events for registration, lockout, auto-expiry, operator unlock) through a pluggable `EventLogger` — file (flushed per line, lock-guarded), console, null, or your own. One-line ASCII format, reversible via `Event.parseLine`.

**Non-obvious correctness points, each pinned by a test**
- *Equal work on all six refusal paths* (unknown user, bad name, bad password shape, corrupt record, disabled, locked), so response time can't enumerate accounts. The dummy digest is generated by a real derivation at construction, not a pasted constant. Measured medians 41–43 ms each; all ratios ~1.0.
- *Password-shape guard*: `PBEKeySpec` collapses `"pw"`/`"pw\0"`/`"p\ud800"` onto one digest, so those are rejected — the test derives the collision with the raw JCE first to prove the guard isn't theater.
- *Log injection impossible*: hostile usernames (`\r\n` + a forged record, `|`, control chars) are neutralized field-by-field.
- *Constant-time key compare*, strict canonical-Base64 record parsing, defensive copying of salt/key.

**Honest caveats in the README:** storage is in-memory (`AccountStore` is the swap-in seam for JDBC), no session/token layer, and the two surviving mutants are genuinely unobservable — `Arrays.equals` vs `MessageDigest.isEqual` is a sub-microsecond difference under a ~40 ms derivation, and one mutant was a semantic no-op.
