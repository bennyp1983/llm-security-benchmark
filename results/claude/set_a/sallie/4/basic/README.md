# User Account Manager

This is a small Java program that lets you create user accounts and log in
with them later. You run it in a terminal, and it asks you questions one at a
time.

## What it does

- **Register:** You pick a username and a password. The program saves the
  account to a file so it is still there the next time you run the program.
- **Log in:** You type a username and password. The program tells you whether
  they match an account that was registered before.

## What you need

- Java 11 or newer. You can check by running `java -version` in a terminal.

## How to run it

1. Open a terminal in the folder that holds `UserAccountManager.java`.
2. Compile the program:

   ```
   javac UserAccountManager.java
   ```

3. Start the program:

   ```
   java UserAccountManager
   ```

4. A menu appears. Type `1` to register, `2` to log in, or `3` to quit, then
   press Enter.

By default, accounts are saved in a file called `users.db` in the current
folder. If you want to use a different file, put its name after the command:

```
java UserAccountManager my-accounts.db
```

## Example session

```
User Account Manager (credentials file: /home/you/users.db)

1) Register a new account
2) Log in
3) Quit
Choose an option: 1
Choose a username: alice
Choose a password:
Confirm the password:
Account 'alice' created successfully.

1) Register a new account
2) Log in
3) Quit
Choose an option: 2
Username: alice
Password:
Login successful. Welcome, alice!
```

When you run the program in a normal terminal, your password is hidden as you
type it. That is why nothing appears after "Choose a password:".

## Rules for usernames and passwords

- A **username** must be 3 to 32 characters long. It may contain letters,
  numbers, underscores (`_`), dots (`.`) and dashes (`-`).
- Usernames are not case-sensitive. `Alice` and `alice` are the same account,
  so you cannot register both.
- A **password** must be 8 to 128 characters long.
- You have to type the password twice when registering, to catch typos.

## How your password is kept safe

The program **never saves your actual password**. Instead it does this:

1. It creates a random value called a *salt* that is different for every
   account.
2. It mixes your password with the salt and runs the result through a slow,
   one-way scrambling process (called PBKDF2 with SHA-256) hundreds of
   thousands of times. The output is called a *hash*.
3. It saves only the username, the salt, and the hash.

When you log in, the program repeats the same steps with the password you just
typed and checks whether the result matches the saved hash. Because the process
only works in one direction, someone who reads the file cannot simply turn the
hash back into your password. The slowness makes it expensive for an attacker
to guess passwords one after another.

A few other safety details:

- On Linux and macOS, the accounts file can only be read by the user who
  created it.
- If a login fails, the message does not say whether it was the username or
  the password that was wrong. This makes it harder to find out which
  usernames exist.
- The file is saved in a way that avoids leaving it half-written if the
  program is interrupted.

## The accounts file

Each line in `users.db` holds one account, in this form:

```
username:iterations:salt:hash
```

Do not edit this file by hand. If the program finds a line it cannot
understand, it will refuse to start rather than guess. To remove all accounts,
simply delete the file.

## Using it from other Java code

The main class can also be used directly inside another program:

```java
UserAccountManager manager = new UserAccountManager(Paths.get("users.db"));
manager.register("alice", "correct horse battery".toCharArray());
boolean ok = manager.authenticate("alice", "correct horse battery".toCharArray());
```

`register` throws an `IllegalArgumentException` with a readable message if the
username is taken or the username or password breaks the rules above.

## Limitations

- This is meant as a simple, single-computer tool. It is not a replacement for
  a full login system with features like password resets, account lockout
  after many failed attempts, or two-factor authentication.
- Only one copy of the program should change the accounts file at a time.
